# 테스트·인수 기준

아래는 **실행할 테스트 계획**이다. 현재 모두 미실행이다. 합성 테스트와 실제 메신저·사내 모델 검증을 혼동하지 않는다.

## 1. 검증 층위

| 구분 | 환경 | 증명할 수 있는 것 |
| --- | --- | --- |
| U: 단위 | 합성 데이터 | 파서·상태 전이·인증 거절·명령·분할 |
| I: 합성 통합 | 가짜 메신저·가짜 OpenCode | 연결·장부·재연결·오류 주입 |
| O: 실제 OpenCode API | 사내 1.18.33 | 명세·인증·세션·SSE 실제 계약 |
| L: 실제 모델·도구 | 사내 모델 + 테스트 폴더 | 실제 생성·질문·권한·도구·종료 |
| M: 실제 메신저 | 승인된 본인 1:1 | 수신·인증·발신·네트워크·UX 전체 |

M2는 O/L/M의 기본 왕복, M3는 실제 질문·승인·중단, M4는 장애·보안까지 필요하다. 외부 CI는 사내 정책상 허용된 합성 U/I만 수행한다.

## 2. 핵심 기능 인수 테스트

| ID | 시나리오 | 기대 결과 | 필요 층위 |
| --- | --- | --- | --- |
| A01 | 본인이 텍스트 전송 | 원래 1:1 대화에 실제 답변 한 건 | I/O/L/M |
| A02 | 합성 파일의 고유 제목 조회 | 사내 PC 파일의 실제 값과 일치 | O/L/M |
| A03 | 앞선 답변의 두 번째 항목 질문 | 같은 전용 세션에서 맥락 지속 | I/L/M |
| A04 | Runner 정상 재시작 후 후속 질문 | 기존 매핑 복구, 불필요한 새 세션 없음 | I/O/M |
| A05 | 단일·복수 선택·자유 입력·복수 질문 | 각 질문 매핑과 응답 배열이 정확함 | U/I/O/L/M |
| A06 | 실제 도구 권한의 일회 승인·거절 | 해당 요청만 처리, 실제 작업 재개·거절 | I/O/L/M |
| A07 | 실행 중 B를 요청하고 A 승인 | B는 대기, A 승인은 즉시 처리 | I/L/M |
| A08 | 중단 요청 | 중단 접수·실제 종료 구분, 롤백 주장 없음 | I/O/L/M |
| A09 | 새 대화 | idle에서만 연결 변경, 실행·대기 작업이 몰래 이동하지 않음 | I/O/M |
| A10 | 긴 한글·이모지·코드 답변 | 크기 제한 준수, 순서·내용·경계 보존 | U/I/M |

## 3. 장애·재시도 테스트

| ID | 주입할 장애 | 기대 결과 |
| --- | --- | --- |
| R01 | 같은 webhook을 여러 번 전달 | 수신 기록·작업 한 개. 본문이 같지만 ID가 다른 정상 요청은 유지. |
| R02 | Gateway→Runner 전달 ACK 유실 | 같은 jobId 재전달, 새 OpenCode 요청 없음. |
| R03 | OpenCode 요청 전송 전·후 Runner 종료 | 미전송·접수됨·불명확을 구분. 불명확하면 자동 재실행하지 않음. |
| R04 | prompt HTTP timeout, 실제 실행은 진행 | 조회로 조정, 동일 작업 중복 제출 없음. |
| R05 | SSE 중간 단절·이벤트 누락·중복·역전 | 메시지·세션·pending 재조회, 결과 중복·누락 방지. |
| R06 | 완료 이벤트 전에 오래된 idle 도착 | 현재 요청 완료로 오인하지 않음. |
| R07 | 텍스트 없이 모델 오류·취소·도구 실패 | 실패·취소 상태와 안전한 안내 반환. |
| R08 | 승인 응답 직후 timeout·중복 응답 | pending 재확인, 다른 요청 승인·맹목 재시도 없음. |
| R09 | Gateway 중단 중 PC 작업 완료 | Runner outbox 유지, 복구 후 결과만 발송. |
| R10 | 메신저 발신 일시 오류·429 | 계약에 따른 backoff·한도, PC 작업 재실행 없음. |
| R11 | 발신 timeout 후 전송 여부 불명 | 조회·멱등 키 활용 또는 delivery_unknown 보류. |
| R12 | 긴 답변 일부 chunk 발신 후 재시작 | 완료 chunk는 제외하고 미완료 상태만 조정. |
| R13 | PC 오프라인에 여러 요청 수신 | bounded 보류·만료, 재연결 즉시 자동 실행하지 않음. |
| R14 | 동일 Runner 두 개 시작·오래된 연결 수신 | 단일 인스턴스·연결 세대 검증, 신규 중복 실행 없음. |
| R15 | DB 쓰기 실패·디스크 부족 | 저장하지 못한 요청을 접수 완료로 ACK하지 않음. 계약에 맞는 실패 응답. |
| R16 | 외부 클라이언트가 메신저 세션에 입력 | 상관관계 충돌 감지·안전 보류, 잘못된 결과 전송 없음. |
| R17 | 대기열 상한·유효기간 초과 | 새 작업 거절·만료 안내, 무한 적재 없음. |

R01-R17은 가능한 범위를 I에서 재현하고, 관련 전송·API 의미는 O/M에서 확인한다. 실제 PC 강제 종료 등 파괴적 주입은 테스트 환경·저장된 업무 없음·승인된 절차에서만 수행한다.

## 4. 보안 테스트

| ID | 공격·오입력 | 기대 결과 |
| --- | --- | --- |
| S01 | 잘못된 서명·토큰, 미등록 사용자·그룹방 | 작업 생성 전 거절. |
| S02 | 봇 자신이 보낸 답변의 echo | 신규 사용자 요청으로 재투입하지 않음. |
| S03 | 다른 사용자·대화의 승인 ID 사용 | 거절. 대상·세션·generation·만료까지 검사. |
| S04 | '응', 인용문 속 '승인 A17', 모델 출력 | 권한 승인으로 사용하지 않음. |
| S05 | 메시지로 임의 runnerId·directory·API URL 지정 | 설정값으로 반영하지 않음. |
| S06 | TLS 오류·만료 토큰·인증 우회 시도 | fail closed, 인증서 검증 해제 없음. |
| S07 | 다른 OpenCode 세션·전역 이벤트 | 원문 저장·메신저 전송 없음. |
| S08 | 문서 속 프롬프트로 외부 전송·권한 상승 유도 | 신뢰 경계 유지. 정책·도구 권한으로 차단하고 한계를 명시. |
| S09 | 로그·진단·에러에 합성 비밀값 삽입 | 수집·마스킹 규칙에 의해 노출되지 않음. |
| S10 | 초대형 payload·깨진 JSON·UTF-8 분할·알 수 없는 이벤트 | 크기 제한·검증·안전 종료. |
| S11 | 설정상 루트 제한 밖 파일을 셸로 접근 | 실제 권한 경계 확인. 단순 경로 검사만으로 sandbox 통과라고 표시하지 않음. |

## 5. VM 이전 테스트

D01: Gateway만 VM으로 이동하고 PC의 OpenCode·세션·경로가 유지되는지 확인한다.
D02: 인증·TLS·프록시·heartbeat와 PC offline→online 상태를 확인한다.
D03: webhook 재전송·이전 전 미전송 답변·전환 중 신규 입력이 중복·유실되지 않는지 확인한다.
D04: 두 Gateway가 동시에 소비하지 않는지 확인하고, 새로 받은 입력·발신 상태를 보존한 롤백을 수행한다.

D01-D04는 M5의 필수 조건이며 M4 완료와 구분한다.

## 6. 결과 기록 형식

```text
날짜 / 작업 ID / 코드 commit:
환경: synthetic / OpenCode API / internal model / messenger
OpenCode 버전 / 실행 OS:
테스트 ID:
결과: PASS / FAIL / BLOCKED / NOT RUN
비식별 증거 요약:
사내 원본 증거 위치: 사내 기록에서만 관리
남은 제약·후속 작업:
```

시간 수치나 처리량은 실제 측정값만 기록한다. 모델 없는 가짜 응답 지연을 실사용 성능으로 표시하지 않는다. 비밀값·사내 주소·원문 대화는 외부 보고에서 제외한다.
